# codepluse · 冰蓝毛玻璃视觉稿

Figma：https://www.figma.com/design/eNjOk5vGAqsntf5eqmGKpH?node-id=9-612

参考用户提供的 IMG_1599.jpeg，仅借鉴冰蓝灰、柔光与半透明磨砂材质；保留 codepluse 原布局、会话侧栏、标签、输入控件、终端、辅助面板和状态栏。

## 材质参数

- 背景：冰蓝灰渐变，三层低对比柔光；装饰层绝对定位，不占据功能布局空间。
- 侧栏：白色 28%，背景模糊 32px。
- 标签与会话标题：白色 25–32%，背景模糊 22px。
- 消息与工具卡片：白色 52–53%，背景模糊 20–22px。
- 输入框：白色 79%，背景模糊 28px，细白描边与轻微阴影。
- 终端：白色 43%，背景模糊 26px。
- 辅助面板：白色 37%，背景模糊 30px。
- 底部状态栏：白色 44%，背景模糊 24px。
- 正文深蓝灰 #202D40，次级文字 #566479，主按钮 #132D51。

使用 Figma 原生 BACKGROUND_BLUR、LAYER_BLUR、透明填充和矢量装饰。文字、图标和界面组件均保持可编辑，未使用完整 UI 位图替代。

画板为 1440 × 960；导出的预览包含外阴影，因此为 1520 × 1040。两种状态：默认会话 `9:612`，终端与辅助面板展开 `9:832`。新增描边不参与自动布局，原内容坐标保持不变。

## 前端落地

已应用到 `codeg-ui/src/app/codepluse-glass.css`，由根布局导入，仅作用于 `.zw-shell` 工作区。输入框原组件、布局、尺寸、字体与内外间距不变；终端仅调整画布透明背景，让所属面板的磨砂表面透出。尊重亮/暗主题和已有工作区背景图，背景图模式的透明度/模糊滑块继续使用原设置。

在现有 Go 服务 8841 上验证：1280×720 视口下，输入框、编辑区、前部工具区和发送按钮区的 x/y/width/height 修改前后完全相同。输入框坐标为 (434, 421.5375)，尺寸为 736×123.6；模型菜单及辅助面板可正常展开，终端可从原入口开关。面板状态已恢复。

生产构建成功生成 39 个页面，终端主题原有 7 项测试通过，修改的 TypeScript 文件通过 ESLint。示例消息不代表服务端实时任务。

## 设置页重构

设置页在用户授权下独立调整布局：浮动玻璃导航、圆角内容面板、统一表单卡片。右上角重复的「偏好设置」入口及导航总览弹窗已按要求移除，移动端仍从原菜单按钮打开导航。工作区与输入框布局不受这些规则影响。共享材质变量由 `codepluse-glass.css` 提供，设置页布局与动效集中在 `codepluse-settings.css`。

卡片支持指针聚光与最大 0.7° 的轻微倾斜；聚光渐变半径由 280px 缩小至 140px，亮暗主题一致。聚焦控件、折叠卡片和系统减少动态效果时停止倾斜。原有折叠内容增加高度与淡入淡出动画。原设置项与保存逻辑保持原实现。

Windows 文档导航启用 View Transitions，侧栏作为共享元素保留，内容淡入切换；不支持此 API 的浏览器正常导航。此次内置浏览器不支持 View Transitions，因此已验证基础导航与卡片入场，未宣称验证了共享元素动画本身。

验证：生产构建成功；设置导航与终端主题共 10 项现有测试通过；修改的 TypeScript 文件通过 ESLint。8841 实际页面检查了常规/外观切换、查询参数保留、导航弹窗、Escape 关闭与焦点恢复、通知卡片展开/收起、聚光 CSS 坐标与三维变换；页面无水平溢出。未修改表单设置值。预览见 `codepluse-settings-live.png` 与 `codepluse-settings-overview-live.png`。
